## 1. 共通のコマンド

### 制御フレーム `ESC { … }`

```
1B 7B <len> <cmd> <params…> <ck> 7D
len = cmd から 7D までのバイト数（= params + 3）
ck  = (cmd + Σparams) & FF
```

| cmd | 意味 | 例 | 確度 |
|---|---|---|---|
| `@` 40 | ジョブの区切り（先頭・末尾） | `1B 7B 03 40 40 7D` | ✅ |
| `{` 7B | ジョブ開始 "ST" | `1B 7B 07 7B 00 00 53 54 22 7D` | ✅ |
| `C` 43 | カット設定（u32） | 下表 | ✅ |
| `D` 44 | 濃度。値 = 濃度 + 5（-5〜+5、0 が標準） | `1B 7B 04 44 05 49 7D` | ✅ |
| `G` 47 | ジョブ設定の終わり | `1B 7B 03 47 47 7D` | ✅ |
| `L` 4C | ページ長（u32 LE、ドット） | `1B 7B 07 4C AA 00 00 00 F6 7D` | ✅ |
| `T` 54 | 先頭の余白（u16 LE、ドット） | `1B 7B 05 54 2A 00 7E 7D` | ✅ |
| `H` 48 | 画像処理モード（SR5900P では 5） | `1B 7B 04 48 05 4D 7D` | ✅ |
| `s` 73 | 印字速度（0 = 高速） | `1B 7B 04 73 00 73 7D` | ✅ |
| `I` 49 | ステータス要求（新しい世代）。`05 00` で自動通知、`00 00` で単発 | `1B 7B 05 49 00 00 49 7D` | ✅ |
| `Q` 51 | ステータス要求（第一世代） | `1B 7B 05 51 00 00 51 7D` | ✅ |
| `!` 21 | リセット | `1B 7B 03 21 21 7D` | 🔶 |
| `+` 2B | 送り（`01` で送り＋カット） | `1B 7B 04 2B 01 2C 7D` | 🔶 |

カットの値（`C`、ハーフカット対応機）:

| 動作 | params | 確度 |
|---|---|---|
| ラベルごとにフルカット | `01 01 01 01` | ✅（SR5900P・SR-R2500P） |
| ラベルの間をハーフカット（最後はフルカット） | `01 02 01 01` | ✅（SR5900P） |
| ラベルごと＋ハーフカット（参考実装の値） | `02 02 01 01` | 🔶 |
| カットしない | `00 00 00 00` | 🔶 |

### ラスタ行 `ESC .`

```
1B 2E 00 <v> <h> 01 <nL> <nH> <ceil(n/8) バイト>
```

- 1 行 = テープ幅方向の 1 列。送り方向に行を並べる。データは MSB first で、1 = 黒。
- n は 1 行のドット数（u16 LE）。
- v/h は機種で決まる: SR3500P `14`、SR-R2500P / SR5900P `00`（SR3700P は `0D`、SR920 は `0A`）。

### 拡張コマンド `ESC ( c nL nH data…`（SR3500P）

| バイト列 | 意味 |
|---|---|
| `1B 28 47 01 00 01` | グラフィックスモードの選択。これがないとラスタ行は無視され、送りだけになる ✅ |
| `1B 28 43 02 00 <nL nH>` | ページ長（ドット）。これがないとジョブ全体が無視される ✅ |
| `1B 28 76 02 00 <nL nH>` | 縦方向の相対移動（ドット）。ラスタ行の前に 1 ドット送る ✅ |
| `0C` / `1B 40` | ページ終了 / ジョブ終了。`1B 40` がないと ST が 03 のまま戻らない ✅ |

いずれも Epson ESC/P2 の公開仕様にあるコマンドです。

### テープ幅コード（ステータスの TW）

| code | 00 | 01 | 02 | 03 | 04 | 05 | 06 | 07 | 0B |
|---|---|---|---|---|---|---|---|---|---|
| mm | なし | 6 | 9 | 12 | 18 | 24 | 36 | 50 | 4 |

`51`〜`5B` は `01`〜`0B` の別名です。

### ステータスの値

| ST | 意味 | | ER | 意味 |
|---|---|---|---|---|
| 00 | 待機 | | 00 | なし |
| 01 | 送り中 | | 01 | カッターエラー |
| 02 | 印字中 | | 06 | テープカートリッジなし |
| 03 | データ受信中 | | 21 | カバーオープン |
| 04 | 送り終了 | | 42 | テープエンド |
| 05 | 印字終了 | | 45 | パラメータ不足 |

### 印字可能ドット数（1 行あたり）

| テープ | 4mm | 6mm | 9mm | 12mm | 18mm | 24mm | 36mm |
|---|---|---|---|---|---|---|---|
| 180dpi（SR3500P、SR-R2500P） | 22 | 36 | 54 | **72** ✅ | 108 | 128 | — |
| 360dpi（SR5900P） | 40 | 72 | 104 | **144** ✅ | 216 | 288 | 368 |

12mm 以外は 🔶 です。180dpi の値は参考資料の印字可能ドット表から、360dpi の値は hikalium/sr5900p の換算（印字幅 mm を 360dpi で 8 の倍数に切り上げ）から取っています。SR-R2500P は 24mm に対応していません。

## 2. SR3500P（USB）

### 接続 ✅

| 項目 | 値 |
|---|---|
| VID:PID | `0D8A:0102` |
| USB | 1.1 Full Speed、Printer class `07/01/02`（双方向）、interface 0 |
| エンドポイント | Bulk IN `0x81`、Bulk OUT `0x02`（64 バイト） |
| IEEE 1284 ID | `MFG:KINGJIM;CMD:ESCPL2;MDL:TEPRA PRO SR3500P;CLS:PRINTER;` |

- macOS はこのインターフェースにカーネルドライバを付けないので、libusb でも WebUSB でもそのまま claim できる。
- Windows（usbprint）と Linux（usblp）では OS が先に掴むため、WinUSB への差し替えや usblp の取り外しが必要（❓ 未検証）。

### ジョブの前の準備 ✅

1. USB プリンタークラスの SOFT_RESET（`bmRequestType=21, bRequest=02, wIndex=interface`）
2. GET_PORT_STATUS（`A1/01`）の Selected ビット（`10`）が立つまで待つ（最大 10 秒）

SOFT_RESET を省くと、2 回目以降のジョブが無視される。

### ステータス ✅

- `ESC { Q 00 00 }` を bulk OUT に送ると、bulk IN に 64 バイトのテキストが返る。

  ```
  @BDC ST\r\nST:00;ER:00;WR:00;RV:00;TW:03;TR:00;CT:03;OP:00;EI:00;  + FF
  ```

  値は 16 進。
- `ESC { Q 05 00 }` で自動通知になり、`ESC { Q 00 00 }` で戻る。
- bulk IN は**パケット長ちょうど（64 バイト）で要求する**。応答はちょうど 64 バイトで、終端の短いパケットが来ない。そのため長めに要求すると、WebUSB では返ってこない。
- ベンダー制御転送 `C1/01`（SR3700P のテープ幅取得）は STALL する。

### ジョブ ✅

```
ESC { D <濃度+5> }                      濃度 0 以外のときだけ
1B 28 47 01 00 01                      グラフィックスモード
1B 28 43 02 00 <ページ長>
1B 28 76 02 00 <先頭の余白>             余白 0 のときは省く
行ごと: 1B 28 76 02 00 01 00 + 1B 2E 00 14 14 01 <n> <data>
0C
1B 40
```

- **行はラベルの末尾から送る**。先頭から送ると左右が鏡像になる。
- 1 行の中は dot 0 = ラベル上端。
- **1 ジョブ = 1 枚**。カットはジョブ終了（`1B 40`）でしか起きず、`0C` で区切った 2 ページ目はつながって出る。`1B 40` の後に続けたデータは SOFT_RESET を挟むまで無視される（送りだけになる）。複数枚は「SOFT_RESET → ジョブ」を枚数ぶん繰り返す ✅。

#### 各要素の要否（実機、12mm、2026-10-20）

ESC/P2 の公開仕様から候補になるコマンドを組み合わせ、要素を 1 つずつ外して送り、印字されたか（ST が 03 → 00 と遷移したか）を見た結果です。

| 外した要素 | 結果 |
|---|---|
| ジョブ前の SOFT_RESET | **必要**。直前のジョブが `1B 40` で終わっていると、次のジョブが無視される |
| `1B 28 47`（グラフィックスモード） | **必要**。送りだけで印字されない |
| `1B 28 43`（ページ長） | **必要**。ジョブ全体が無視される |
| 行ごとの `1B 28 76 … 01 00` | **必要**。外すと行が重なる。`1B 4A 01`（ESC J）に替えると長さが縮む |
| `1B 2E` の v/h = `14` | **必要**。`00` にすると長さが縮む |
| `1B 40`（末尾） | 印字はされるが ST が 03 のまま戻らない。送る |
| `ESC { D }` | 不要（濃度の指定にだけ使う） |
| 先頭の `1B 28 76`（余白 0） | 不要 |
| `0C` | 外しても印字される。ページの区切りにはならない（上記）。送る |
| （追加）`1B 40` + `1B 28 47` を挟んで 2 ページ目 | 2 ページ目は無視され送りだけになる |

## 3. SR-R2500P（Bluetooth Classic SPP）

### 接続

- RFCOMM は 2 本ある。ch6 = SerialPort（UUID `1101`）がデータ経路で、ch1 は別サービス。ServiceClass の UUID で選ぶ ✅。
- **BLE（Bluetooth Low Energy）の広告は出していない**。電源が入り Classic で応答する状態で、macOS の CoreBluetooth で 30 秒ずつ走査しても、本機らしい広告は見つからなかった ✅。そのため Web Bluetooth（GATT のみ）からは使えず、ブラウザからは Web Serial（RFCOMM）を使う。
- **macOS**
  - `/dev/cu.<機器名>` は、一度閉じるとリンクが張り直されず、2 回目以降は通信できなかった ✅。
  - 本リポジトリの中継アプリ（`tools/bt-bridge`）は、IOBluetooth でベースバンドを張り直し（`closeConnection` → `openConnection`）、SDP で SPP のチャネルを探してから RFCOMM を開く。これで繰り返し接続できた ✅。
  - Bluetooth の利用許可は「起動元のアプリ」で判定される。そのため中継アプリは `.app` として `open` で起動する ✅。
  - `openRFCOMMChannelSync` は、ランループの回っているメインスレッドから呼ぶ ✅。
- **ブラウザ（Chromium 系の Web Serial）**
  - `allowedBluetoothServiceClassIds` に SPP の UUID を渡すと開ける ✅。
  - リンクが張られていない状態（`port.connected === false`）からの**最初の `open` は、約 10 秒後に `NetworkError: Failed to open serial port` で失敗する**。`open` を始めて 1 秒前後で `connect` イベントが届き `connected` が `true` になるので、直後に開き直すと 0.25 秒ほどで開ける ✅。
  - **リンクが切れても（電源オフなど）、Chrome はポートを閉じない**。`disconnect` イベントは届くが、`readable` / `writable` が残った「半開き」になり、次の `open` は `InvalidStateError: The port is already open` で失敗する。読み取りは `NetworkError: The device has been lost` になる。選び直し（`requestPort` / `getPorts`）でも同じポートが返る ✅。
  - 半開きのポートは `close()` で閉じられ（10 ms ほど）、その後は上の手順（最初の `open` の失敗 → 再試行）で開き直せる。ブラウザの再起動は要らない ✅。以前に「再起動するまで開けない」と見えていたのは、この半開きを閉じていなかったため。
  - ライブラリ（`WebSerialChannel`）は、`open` の前に半開きのポートを閉じ、`disconnect` を受けた時点でも閉じる。`open` は 3 回まで再試行する。
  - 確認環境: macOS、Chromium 155（Brave）、2026-10-21。調査には `examples/web/bt-diag.html`（各操作の結果とイベントを記録する診断ページ）を使った。
  - Android 版 Chrome は 137 から Web Serial の Bluetooth RFCOMM に対応している（[Chromium の Intent to Ship](https://groups.google.com/a/chromium.org/g/blink-dev/c/BqUGCcurReE/m/XbuAYkRxEQAJ)）。ただし Android では `connected` と `connect` / `disconnect` イベントが完全には使えないとされている ❓ 未検証。
  - 開いたまま止まると、ブラウザを終了するまで SPP が解放されない。そのため `open` は 15 秒、送信は 30 秒で打ち切り、必ず `close` する。

### 手順（commandLevel 5） ✅

```
ESC { I 05 00 }      自動通知 ON → ステータスを待つ（テープ幅を照合）
@  {ST  C 01 01 01 01  D  G
ESC { I 05 00 }      → ステータスを待つ
L <行数>  T <余白>
(1B 2E 00 00 00 01 <n> <data>) × 行数     1024 行ごとにステータスを確認
0C  @                → ST 02（印字中）→ 05（印字終了）→ 00
ESC { I 00 00 }      自動通知 OFF（省くと次の接続でステータスが取れない）
```

- 参考手順にある最初の `ESC { ! }`（リセット）は送らない。macOS では、送った直後に Bluetooth のリンクが切れ、本体の電源を入れ直すまで戻らなかった ✅。
- 行はラベルの先頭から送る。1 行の中は dot 0 = ラベル下端 ✅。

### ステータス（92 バイト） ✅

```
40 42 44 43 20 53 54 32 0D 0A 50 00 3B | 本体 78 バイト | 1 バイト
"@BDC ST2\r\nP\0;"                       [1]=ST [2]=ER [3]=TW
```

## 4. SR5900P（LAN）

### 探し方

mDNS の `_pdl-datastream._tcp` で、`SR5900P<MAC 下位>.local` として見つかる ✅。TXT に `usb_MDL=TEPRA PRO SR5900P` が入る。

### 制御（UDP 9100、TPRT） ✅

ヘッダは 32 バイト、ビッグエンディアン。

```
"TPRT"（応答は "tprt"）| 00000000 | 00000001 | 00000020 | cmd | data_size | 0 | 0
```

| cmd | 意味 | 応答データ |
|---|---|---|
| 1 | ステータス | 20 バイト: [0]=`14` [1]=ST [2]=ER [3]=TW |
| 2 | 印刷開始（TCP 9100 が開く） | `02 00 00` |
| 3 | 印刷終了 | `03 00 00` |
| `0101` → `0100` | データ送信の通知 | `0100` の応答は `10`（時に `00`） |

応答は、送った cmd と一致するものだけを採る。

### 手順 ✅

1. 状態(1) で、エラーがなく・印字中でなく・テープ幅が一致することを確かめる
2. 印刷開始(2) → 0.5 秒待つ
3. TCP 9100 に接続 → 0.5 秒待つ
4. 通知（`0101` → `0100`）→ 0.5 秒待つ
5. データを送信する
6. 0.5 秒ごとに状態(1) を確認し、印字中が終わるのを待つ
7. 印刷終了(3)。途中で失敗した場合も必ず送る

### データ（TCP） ✅

```
@  {ST  C <先頭> <ラベルの間> 01 <末尾>  D  G
（L <行数+4>  T 00 00  H 05  s 00
  (1B 2E 00 00 00 01 <n> <data>) × 行数
  0C）× ラベルの枚数
@
```

- **行はラベルの末尾から送る**。1 行の中は dot 0 = ラベル上端。
- 複数枚は、1 つのジョブの中にラベルごとの `L` 〜 `0C` を並べる ✅。`C` の 2 バイト目が**ラベルの間**のカットで、`01 02 01 01` ならハーフカットでつながって出る（2026-10-29、9mm）。
- `@` 〜 `@` のジョブ全体を 1 回の送信で 2 回以上続けると、何も印字せず、印刷終了(3) を送るまで状態(1) にも答えなくなる ✅。この状態のあと、数分して本体の電源が落ちることがあった。
- `T`（先頭の送り）が `2A 00`（42）だと、ジョブの先頭で短い片が切り落とされる。`00 00` にすると片は出ない ✅（2026-10-29、9mm）。
- `C` の 1 バイト目（先頭）を `00` にすると片は出ないが、印字の先頭が数 mm 欠け、ラベルの前に 1 cm 近い余白が残る ✅。
- `C` の 3 バイト目を `00` にすると、最後のカット（とその前の送り）が無くなり、テープが中に残る ✅。4 バイト目は `00` にしても見える違いがない。
- **カット位置**（2026-10-29、9mm、2〜3 枚つなぎで実測）✅:
  - 本体は、ジョブの先頭と **1 枚目の後ろだけ**に、約 33 ドット（≒ 2.3 mm、ヘッド〜カッター間と思われる）の空白を自分で入れる。
  - ラベルの間のカットは、次のラベルのデータの始まりに入る。最後のカットは、データの終わりに入る。2 枚目以降は、データの境目でほぼ 0 の位置に切れる。
  - そこで labelbridge は、2 枚目以降の前後（1 枚だけのときはその後ろ）に空白を足して、各ラベルの前後の余白をそろえる（`sr5900pLayout`）。既定（余白 33 ドット）は前 43・後ろ 31。
  - 余白を 33 ドットより狭くするときは、先頭に空のページ（8 行）を入れ、本物のラベルを全部「2 枚目以降」にする。このとき最初のラベルの後ろだけ 7 ドット短くなるので足す。
  - これらの値は機体やテープで変わりうるので、`Sr5900pCalibration` で渡せるようにしてある。

## 5. 情報の出どころ

本書と本リポジトリのコードは、次の 3 種類の情報から成ります。項目ごとの出どころは下の表のとおりです。

1. **公開仕様**: Epson ESC/P2、USB Printer Class（USB-IF）、メーカーの取扱説明書
2. **参考にした OSS**（下記。参照したコミットを固定して記載）。取り入れたのはコマンドの意味・手順・数値といった**事実**で、コードや文章は転載・翻案していません
3. **実機観測**: 当方所有の 3 台での印字・ステータス読み取り（§2〜§4 の ✅）

参考 OSS のうち、[nikachu2012/tepra_web](https://github.com/nikachu2012/tepra_web) の PROTOCOL.md は、作者がメーカーのアプリを解析して書いた資料です。本プロジェクトはその資料に書かれた**プロトコルの事実**（手順・ステータス形式・ドット表・カット値）を参照し、実機で確かめたうえで使っています。
